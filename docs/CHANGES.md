# 相对原版（dsh-bili-scroll）的主要更改

> 原版：`c1overzz/dsh-bili-scroll`（DSH 插件，MIT）
> 本版：BiliPick（独立 App，MIT），沿用同一产品思路重写

## 1. 形态：插件 → 独立 App

| | 原版 | BiliPick |
|---|---|---|
| 运行环境 | 依赖 DSH（host 半端 + headless 会话） | 不依赖 DSH，自带本地 Web 服务 |
| 界面 | DSH 设置页里的单页表单 | 独立浏览器界面，左侧分栏（总览/类别与配额/API 与模型/运行/日报/高级） |
| 运行依赖 | 需要 DSH + Python MCP | 只有 Python（或打包成 exe，免 Python） |
| 分发 | `dsh plugin add` | 源码 / 免安装 exe 目录 |

## 2. 交付方式：评论 @ → 只进「稍后再看」

- 原版：挑中的视频写日报，可选在评论区发一条评论 **@ 使用者**。
- 本版：**不发任何公开评论**，只把挑中的加进「稍后再看」，零社交副作用、零账号风控敞口。

## 3. 选择逻辑：关键词巡检 → 类别配额

- 原版：固定几组关键词搜索，按「每天最多几条」控制总量。
- 本版：
  - 类别化：科技 / 科普 / 生活 / ACGN / 其他，各自配额（默认 5/5/5/10/5 = 30 条/天）；
  - 类别可增删、关键词/条数/精判条数/质量分下限/评分下限都可配；
  - 每个类别分别粗排、精判，再按配额取，保证类别比例。

## 4. 判据：字幕 + 观众评论 + 质量分

- 素材：标题/简介/时长/播放 → 字幕（默认 8000 字）→ 高赞评论（默认 30 条）。
- 质量分（免费）：`播放/点赞/收藏/弹幕/评论` 的对数加权，低于类别下限不进候选。
- 模型精判：0–10 分，**必须引用字幕原句**作为依据；评论里高赞骂「标题党/注水」要扣分，补干货加分。
- 不凑数：低于评分下限不收，某类别可能不满配额。

## 5. 去重：四路合并

- 已关注 UP：**全量**拉取（原版没有这一步）；
- B站 观看历史（最近 N 页，默认 250 条）；
- 历史推荐/评估记录（`seen.json`）；
- 当前「稍后再看」。
- 另外**每天只挑满一次**：当天已挑够配额时再点「开始跑一轮」会直接跳过。

## 6. 成本控制：预算 + 时间双上限

- 默认 ¥3/天、单轮 10 分钟；任一上限到顶自动收尾。
- 逐次调用记账（token 用量 × 空闲/高峰单价），日报里给出本轮实际花费。
- 默认模型 `deepseek-flash`，空闲时段（12–14、18–09、周末）价格约高峰一半。

## 7. 模型接入：单协议 → 四协议

| 协议 | 覆盖 |
|---|---|
| OpenAI 兼容 | DeepSeek、Moonshot、通义、Ollama、vLLM、one-api… |
| Anthropic | `/v1/messages` |
| Gemini | `v1beta/models/{model}:generateContent` |
| 自定义 JSONL | 完整 URL，兼容 JSON 响应或 `data: {...}` 流式逐行 |

API Key 与模型默认留空，由使用者填写；Key 只存本机。

## 8. 运行形态

- 单实例：固定端口 61420，重复启动只会打开已运行实例的界面，不重复开服务、不重复跑。
- 本地服务只监听 `127.0.0.1`，每次启动生成随机 token；接口需带 token。
- 开机自启：Windows 启动文件夹 VBS / 计划任务（登录时静默启动）。
- 免 Python 分发：PyInstaller onedir 打包；注意 Windows Defender 对未签名 exe 可能误报，需要加入排除。

## 9. 未改变 / 保留的部分

- 产品思路与「值班章程」里的经验（空字幕=没语音、硬字幕读不到、失败不重试、引用原文）保留。
- B站 接口仍基于 `bilibili-api-python`（原版内置的 `bilibili-mcp` 也基于它）。
- 仍不碰发送视频/动态/私信等写操作。
